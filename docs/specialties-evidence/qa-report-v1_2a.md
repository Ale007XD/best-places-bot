## 3. Визуальная верификация: метод и ограничения

Прямое скачивание видеопотока в песочнице заблокировано YouTube (bot-check / HTTP 429 на все player-клиенты). YouTube storyboard без подписи также отдаёт HTTP 403, а watch-страница со spec storyboard недоступна. Задокументированные попытки: подписанные storyboard-URL (403), yt-dlp с player_client web/android/ios/mweb/tv_embedded (Sign-in-to-confirm), innertube API (LOGIN_REQUIRED), googlebot UA (страница отдаёт капчу).

Фактический метод: **preview frames** — кадры видеопотока (начало/середина/конец ролика) из служебного набора `i.ytimg.com/vi/{id}/hq1|hq2|hq3.jpg` + thumbnail. Типы кадров строго разведены в manifest: `preview_frame` ≠ `storyboard_frame` ≠ `thumbnail`; storyboard не использовался вовсе (зафиксировано в manifest).

Ограничения метода, отражённые в каждом inspection-блоке:
- `full_video_watched: false` везде;
- точные временные отметки кадров недоступны → `timestamp: null`, `timestamp_seconds: null` (ничего не выдумано);
- изучение ограничено ~4 позициями ролика, поэтому video_confidence по новому рубрику ограничено.

## 4. Новая схема evidence

Каждая из 113 записей `youtube_evidence` получила блок `inspection`:
- `method: "preview_frames"`, `full_video_watched: false`;
- `visual_dish_match` / `visual_location_match` / `commercial_availability` — HIGH/MEDIUM/LOW на основе структурированного анализа кадров (модель зрения описывала видимое блюдо, вывески, адреса, контекст продажи; сверка с эталонным составом специалитета — например, для cao lầu проверялись именно толстая лапша, малое количество соуса, свинина, зелень и хрустящие рисовые компоненты, а не «миска с лапшой вообще»);
- `sampled_frames` — пути к реально существующим файлам кадров (проверено скриптом);
- `limitations` — явные ограничения (рецептурный канал, город только по заголовку и т.п.).

Визуальное сходство нигде не трактовалось как доказательство происхождения блюда; городская привязка оценивалась по читаемым вывескам/адресам/геопризнакам, а «город в заголовке» помечался как слабое доказательство.

## 7. Переоценка video_confidence

Оценки не повышались автоматически относительно v1_2 (кроме com_tam, где повышение обусловлено реально восстановленными доказательствами).
