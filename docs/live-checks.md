# Живые проверки после деплоя

Что нельзя проверить моками. Выполняется один раз после выкатки изменений; каждая проверка — команда
и ожидаемый результат. Команды `docker compose exec telegram-bot python -m bot.diag …` запускаются на VPS.

## 1. Сервисы и данные
| Проверка | Команда | Ожидание |
|---|---|---|
| Все сервисы живы | в боте `/diag` (админ) | ✅ Redis, Telegram, Geoapify, Nominatim; Overpass может быть ❌ — это не критично, пока работает Geoapify |
| Foursquare закрытые места | `diag raw <lat> <lon>` рядом с местом, которое Google показывает «закрыто навсегда» | у такого места `closed=` не пустое; если у всех `None` — FSQ эти места не помечает, одной `date_closed` недостаточно |
| Категории FSQ для серверного фильтра | `diag cats 10.7769 106.7009` | список id подкатегорий — пришлите вывод, чтобы убрать локальный kind-фильтр |
| Точность геопозиции | отправьте боту точку **с карты** (скрепка → Геопозиция → выбрать место), затем поиск | строки «Геопозиция неточная…» нет (`horizontal_accuracy` у такой точки пуст) |
| Чистка старых записей | `diag purge-meta`, затем `diag purge-meta --apply` | после `--apply` «не из OSM/Geoapify» = 0 |

## 2. Найти блюдо
| Проверка | Команда | Ожидание |
|---|---|---|
| Совпадения и обрезка | `diag dish hanoi:pho_bo_hanoi` (из центра города) | совпадения на радиусах 100–500 м; строка «НАБОР ОБРЕЗАН» — признак лимита Geoapify (100 мест); если она частая, нужен целевой запрос по названию |
| Слова из названий | `diag dish ho_chi_minh:com_tam_saigon 10.78 106.70` | у каждого «написания» счёт не нулевой там, где такие заведения есть |
| Поиск текстом | в боте напишите `pho` (при точке в Ханое) | три ближайших заведения с «Phở» в названии, заголовок 🍜 |

## 3. Канал, объявления, сайт
1. Settings → Pages → Source: **GitHub Actions**; после пуша открыть `https://<владелец>.github.io/<репозиторий>/`.
2. Бот — администратор канала с правом публикации; в `.env` `CHANNEL_ID=@канал`, `ADMIN_ID` задан.
3. Actions → **announce** → Run workflow: `tag` существующего релиза, `dry_run=true` — текст появится в логе.
   Затем `dry_run=false`, `mode=approval`: черновик придёт вам в бот; нажмите «✅ Опубликовать» — пост в канале.
4. Settings → Actions → General → «Allow GitHub Actions to create and approve pull requests» (для словаря и переводов).
5. Actions → **dictionary** → Run workflow: `mode=city`, `city_id=next` — должен появиться PR с `verified: false`.

## 4. Бот
- `/deleteme` → «Отмена» ничего не меняет; «Данные профиля» удаляет настройки и геопозицию, баланс остаётся (`/me`).
- Нажмите «🚫 Закрыто» под тестовым местом с двух аккаунтов: место пропадает из выдачи, `/closed` показывает его, `/unhide <id>` возвращает.
- В @BotFather: `/setinline` (включить + подсказка в поле ввода), `/setinlinegeo`.

Если что-то не сошлось — пришлите вывод команды: по нему исправим данные или код.
